# 地图缩放与点位显示

这版保留每个独立点位，不使用数字聚合标记。信息密度由屏幕上的实际地图大小决定，地理坐标和筛选记录不随排版改变。

## 调研与取舍

- [Mapbox 标签排版](https://docs.mapbox.com/help/dive-deeper/optimize-map-label-placement/)建议做碰撞检测，并尝试多个文字锚点。这里对名称和内容采用右、左、上、下避让；空间不足时暂缓显示文字，点位继续保留。
- [Google Maps 标记碰撞与缩放](https://developers.google.com/maps/documentation/javascript/advanced-markers/collision-behavior)将标记优先级与缩放可见性分开处理。本项目依照用户要求，不采用隐藏低优先级点位的方式。
- [NN/g 渐进披露](https://www.nngroup.com/articles/progressive-disclosure/)建议先提供主要操作，再按需呈现高级选项。地图默认自动显示；文字密度和自动放大设置放在“筛选 → 地图显示”。
- [W3C 点击目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)强调尺寸和间距。全图手机点位为 24 像素且独立避让，放大后增至 44 像素；其他地图控件保持至少 44 像素。

这些资料提供设计原则，不构成对本项目体验的用户研究结论。具体阈值通过现有地图数据和多尺寸浏览器验证确定。

## 行为

| 状态                         | 点位与文字                                       | 点击                                     |
| ---------------------------- | ------------------------------------------------ | ---------------------------------------- |
| 全图，地图边长小于 800 像素  | 独立图标；手机 24、桌面 28 像素                  | 普通位置直接操作；密集处放大到目标附近   |
| 区域，地图边长 800–1499 像素 | 名称逐步出现；手机点击区域增大到 44 像素         | 选中的区域不反复要求放大，下一次直接操作 |
| 近看，地图边长至少 1500 像素 | 名称、已确认／候选推断状态、未确定内容的候选类型 | 已确定位置直接看描述，未确定位置选择内容 |

桌面有更多空间，因此可以更早显示名称。阈值使用地图实际像素边长，而不是统一的缩放倍率。文字从不覆盖点位、其他文字和固定地图控件；放不下的文字通过继续放大或点击点位查看。

相邻或同坐标点位分别避让，细线和小圆点指回真实坐标。避让不改变档案数据。点击密集区域只改变视野，不生成筛选条件；可通过“返回放大前”恢复。键盘已明确选定某个点位时直接打开，不强制再次选点。已确定点位仍然直接打开描述。

“自动／只显示点位／显示名称／显示详细内容”和自动放大开关保存在当前标签页内。存储受限时仍可使用。关闭自动放大后，独立点位与防重叠继续生效。缩小或全图复位后可重新触发自动放大。

## 验证

`tests/map-layout.test.js` 检查六种地形、四种窗口、四档缩放（96 组），保证视野内点位保全、互不覆盖、文字不覆盖点位与控件；另验证同坐标点位、布局稳定性和渐进披露阈值。

`tests/map-zoom-browser.py` 在 Chromium 和 Firefox 实测五种窗口（含手机横屏）与六档缩放，验证标签避让、真实触屏点击放大、再次点选、返回视野、键盘、显示配置恢复与已确定点位描述。原有遗物、地图、扩展地图、故障恢复及无障碍检查继续执行。

地图文字只显示确定的首领／强敌名称，去掉建筑前缀。未确定时不生成文字标签，放大也不展示据点类别、建筑类别或候选类型。神授塔只展示已确定楼层的首领。地名、方位等资料默认折叠；原有点选与筛选保留。
