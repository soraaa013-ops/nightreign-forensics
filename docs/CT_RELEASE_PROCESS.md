# CT 与本地写入工具发布门禁

Linux 服务器可以生成遗物 ID、效果 ID、正确排序、版本清单和文件校验值，但不能证明 Cheat Engine 地址或写入行为在 Windows 游戏进程中有效。因此任何 CT 发布必须经过以下门禁。

## 发布前必须具备

1. 明确的游戏版本与 Steam Build ID。
2. 明确的 Cheat Engine 最低与已验证版本。
3. CT 来源、许可证和上游 Commit。
4. 离线、禁用 EAC 的专用测试环境。
5. 修改前存档备份及 SHA-256。
6. 至少覆盖新增、修改、清空和恢复遗物的测试。
7. 写入后的存档能重新读取，并通过同版本合法检测器。
8. 游戏正常启动、遗物可显示、可装备、可卸下和可删除。
9. 发布文件 SHA-256 与测试文件完全一致。

## 强制失效条件

以下任一项发生时，下载页必须默认标记“不兼容”，直到重新验证：

- 游戏版本或 Steam Build ID 变化。
- 存档结构变化。
- Cheat Engine 版本变化导致脚本报错。
- 上游 CT 或地址链变化。
- 合法检测规则包版本变化且影响遗物字段。

## 发布清单

每个 CT 发布必须附带符合 `schemas/ct-release-manifest.schema.json` 的清单。未达到 `verified` 状态的文件不得出现在正式下载按钮中。

## 用户安全说明

- 任何写入前先备份存档。
- 仅在离线且明确禁用 EAC 的环境操作。
- 不承诺零封禁风险。
- 不把测试存档、Steam 标识或账户信息上传到网站。
- 网站生成的“改造单”只说明字段与合法组合，不代表已验证内存地址。
